## Главное событие заезда: сломанная сборка

Первая же попытка `npm run build` после портирования v1.2 дала **SIGKILL** build worker'а.
Дальше пошло по цепочке ложных гипотез:

1. «Мало RAM» → добавил `experimental.cpus: 1, workerThreads: false, memoryBasedWorkersCount` — не помогло.
2. «Мой новый код» → откатил `experimental` — не помогло.
3. «Побитый кэш npm» → `node_modules/next` оказался **12 КБ с пустым `dist/`**, при том что npm
   отрапортовал `added 448 packages, exit 0`. Почистил кэш, переустановил (801 МБ) — **всё равно SIGKILL**.
4. Только тогда сделал контрольный эксперимент: собрал **минимальное** Next.js-приложение в `/tmp`
   в той же песочнице → собралось за 47 с. Значит, среда ни при чём, дело в проекте.
5. Бисекция: закомментировал импорт 3D-сцены → **сборка прошла**. Виновники —
   `three` + `@react-three/fiber` + `@react-three/drei`.

**Вывод, который стоит запомнить:** прежде чем винить окружение, соберите минимальный
воспроизводимый пример в этом же окружении. Это заняло 47 секунд и сэкономило час.

### Что сделали

- Удалили `three`, `@react-three/fiber`, `@react-three/drei`, `@types/three` из зависимостей
  (node_modules 801 МБ → **636 МБ**).
- `sphere-scene.tsx` (R3F) удалён; вместо него `three-sphere.tsx` на «чистом» three.js
  **без типов пакета** — описаны только реально используемые поверхности API.
- three.js грузится **с CDN по требованию** (`jsdelivr`, `three@0.186.1`), в сборку не попадает.
- `ProgressSphere`: по умолчанию лёгкая CSS 3D-сфера, WebGL включается переключателем «3D: CSS / 3D: WebGL»
  (выбор в `localStorage`). Позиционируется в `requestAnimationFrame`.
- Побочный плюс: демо и прод теперь выглядят одинаково — в демо всегда была CSS-сфера.
- Сборка: **~30 с, exit 0, 14 маршрутов**.

## Найденные и исправленные баги

1. **SIGKILL при сборке** — см. выше. Это блокер деплоя, без него v1.2 нельзя было бы выкатить.
2. **Побитый кэш npm** даёт «успешную» установку с пустыми пакетами. Симптом легко принять за OOM.
   Лечение: `rm -rf node_modules && npm cache clean --force && npm install`.
3. **Тест «поиск по каталогу» падал из-за моего запроса, а не кода** — второй раз за два дня:
   вчера «бег» (в «про**беж**ка» нет «г»), сегодня «вода» (в каталоге «Стакан **воды**»).
   Поиск работал правильно оба раза. Заменено на «воды» + добавлена проверка пустого результата.
4. `dnd.offset` вызывал ре-рендер на каждый пиксель движения → округление до 2 px.
