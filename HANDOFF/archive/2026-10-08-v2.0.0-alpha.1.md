## 3. Грабли среды (проверено на себе — НЕ повторять)

### Файловая система и песочница
1. 🔴 **Внутри файлов песочница подменяет литерал `/home/user` на `"$ARENA_WORKSPACE"`.**
   Симптом: `ENOENT: no such file or directory, open '/home/user/...'`, хотя `fs.existsSync` из
   `node -e` возвращает `true`. Лечится: **никогда не хардкодить абсолютные пути в файлах** —
   только `__dirname`, `process.cwd()`, относительные пути. Я потратил на это 6 итераций.
2. 🔴 **`/tmp` нестабилен между вызовами bash.** Пакеты, установленные в `/tmp/node_modules`,
   исчезают. Dev-зависимости ставьте в рабочую область (`tests/package.json`), не в `/tmp`.
3. 🔴 **`npm install`/`node_modules` НЕ сохраняются между сессиями** (папка исключена из снапшота).
   В начале каждой сессии: `npm install` и в `app/`, и в `tests/`.
4. `write_file` **не может писать вне `/home/user`**. Файлы в `/tmp` создаются только через bash heredoc.
5. Снапшот ограничен ~128 МБ / 10 000 файлов. **Удаляйте `.next`, `tsconfig.tsbuildinfo`, `node_modules`**
   в конце работы (я это делаю, продолжайте).

### Bash-инструмент
6. Состояние **не сохраняется между вызовами**: `cd`, переменные, алиасы, фоновые процессы.
7. Таймаут по умолчанию 30 с (максимум 1800). Для `npm install` и `next build` ставьте явно.
8. Нет tty, stdin закрыт → интерактивные программы не работают.
9. `ps` **не установлен**. Процессы не посмотреть.
10. Не установлены: `curl`, `wget`, `ffmpeg`, `pandoc`, `libreoffice`, `imagemagick`, `jq`, `sqlite3`,
    `gcc/g++/make`, `tesseract`. **Компилятора C нет** → пакеты, требующие сборки, не встанут.
    HTTP из bash — через `python3 -c "import urllib.request…"`.
11. 🔴 **Никогда не запускайте `npm uninstall -g <что-угодно>`** — это снесло мне `/tmp/node_modules`
    вместе с jsdom. Глобальные операции npm в этой среде непредсказуемы.
12. **Никогда не запускайте `npx tsc`, если локального tsc нет** — npx скачает фейковый пакет `tsc@2.0.4`
    и замусорит глобальный node_modules. Только `./node_modules/.bin/tsc` или `npm run typecheck`.

### Next.js / сборка
13. 🔴 **RAM песочницы ~1 ГБ** (`MemTotal: 1083460 kB`). `next build` на Turbopack **убивается по памяти**
    (exit 137, слово `Killed` в логе). Поэтому в `package.json` зафиксировано
    `"build": "next build --webpack"`. Не переключайте на Turbopack.
14. 🔴 **Next 16: `middleware.ts` устарел** → файл называется `src/proxy.ts`, функция `proxy()`.
15. **Next 16 + webpack-конфиг = ошибка сборки.** Нужен `turbopack: {}` в `next.config.ts`
    (или явный флаг `--webpack`, что у нас и сделано).
16. Скриншоты/превью HTML рендерятся в **sandbox-iframe без сети** → внешние CDN не грузятся.
    Только inline-стили, встроенный SVG, data URI.

### Supabase
17. 🔴 **Legacy-ключи `anon`/`service_role` (`eyJ…`) выводятся из обращения до конца 2026.**
    Новые: `sb_publishable_…` и `sb_secret_…`. Код уже читает `SUPABASE_SECRET_KEY` с фолбэком
    на `SUPABASE_SERVICE_ROLE_KEY`. В новых инструкциях упоминайте оба варианта.
18. Edge Functions **автоматически получают** `SUPABASE_SECRET_KEY` из окружения — отдельный секрет не нужен.
19. 🔴 **supabase-js на Node 20 падает** при создании клиента: `Node.js detected but native WebSocket not found`.
    В серверных скриптах нужен полифилл: `if (typeof globalThis.WebSocket === 'undefined') globalThis.WebSocket = require('ws')`.
    Уже добавлен в `scripts/import-demo.ts`. `ws` и `@types/ws` — в devDependencies.
20. `.nvmrc` = 22, `engines.node >= 20.9`. Рекомендовать пользователю Node 22+.
21. Free-план Supabase **паузится через 7 дней без активности** — напоминайте об этом.

### React / библиотеки
22. 🔴 **Framer Motion перехватывает `onDragStart/onDragEnd/onDragOver`** собственными типами (`PanInfo`) —
    HTML5 drag-and-drop на `motion.*` не компилируется. Решение: обычный `<article>`,
    анимацию появления делает `AnimatePresence` в родителе.
23. 🔴 **`e.currentTarget === null` после `await`** в обработчике. Кэшируйте ссылку на элемент
    ДО await (`const el = e.currentTarget`) или берите её заново из DOM. Был реальный баг в v1.0.
24. В spread нельзя передавать `{ id: undefined }` — он перезатирает сгенерированный id.
    Делайте `delete copy.id`, а не `{ ...h, id: undefined }`. Был реальный баг.
25. В SQL `plpgsql` **порядок создания функций важен**: `current_streak` вызывает `is_due_on`,
    поэтому `is_due_on` должна быть создана раньше. В `06_…sql` они уже в правильном порядке.

### Тесты
26. 🔴 **Дебаунс `save()` = 120 мс** → проверку localStorage оборачивать в `setTimeout(…, 500)`.
27. 🔴 **Процесс не завершается сам** из-за `setInterval` в приложении → в конце теста обязателен
    `process.exit(0)` / `process.exit(1)`. Иначе bash-вызов висит до таймаута.
28. jsdom **не умеет навигацию** → скачивание файла через `<a download>` даёт `jsdomError:
    Not implemented: navigation`. Это НЕ баг приложения — в харнессе такие ошибки фильтруются.
29. 🔴 **Считайте ожидаемые значения руками, а не «на глаз».** Два теста из семи в v1.1 сначала упали
    из-за моей арифметики, а не из-за кода: (а) замороженный день НЕ входит в `cur` (он продолжает
    цепочку, но не инкрементирует); (б) `start = today − 5` даёт 6 дней, а не 5.
30. Тест должен быть **детерминированным**: не выбирать случайную привычку из сида
    (сид намеренно оставляет часть сегодняшних выполненными), а создавать свою.
31. 🔴 **НИКОГДА не стройте тестовые данные как «N дней назад» с жёстким ожидаемым значением,
    если логика зависит от календарного месяца.** Реальный случай: тест заморозок, написанный
    7 октября, упал 8 октября — `t-7` переехал из сентября в октябрь, а бюджет заморозок помесячный.
    Либо фиксируйте даты абсолютно, либо вычисляйте ожидание от фактического месяца
    (`sameMonth ? 5 : 8`).

## 4. Критическая доменная логика (не сломать!)

### Расписание (`dueOn` / `is_due_on`)
5 типов: `daily` · `weekdays` (`freq_days`: **0 = Пн … 6 = Вс**) · `interval` (каждые N дней от `start_date`)
· `weekly` (`freq_days[0]`) · `monthly` (`freq_days` = числа 1…31).
Плюс границы: `key < start_date` → false; `end_date` && `key > end_date` → false; `archived` → false.

⚠️ **Нумерация дней: 0 = понедельник** (не воскресенье!). И в TS, и в SQL (`extract(isodow) - 1`).

### Стрик — семантика, которую нельзя менять молча
1. Считается **только по плановым дням**, не по календарным.
2. **Сегодняшний день не обнуляет стрик**: если сегодня плановый день ещё не закрыт,
   счётчик показывает стрик по вчерашний день включительно. После отметки вырастает на 1.
   *(Это был баг v1.0 — утром пользователи видели «0». Не откатывать!)*
3. `done` и `skip` продолжают стрик **и инкрементируют счётчик** (`skip` = осознанный отдых, даёт меньше XP).
   **Замороженный `miss` продолжает стрик, но счётчик НЕ инкрементирует** — см. граблю №32.
4. `miss` рвёт стрик, **если** в его календарном месяце не осталось заморозок.
5. День **без записи** (`null`) стрик рвёт и заморозкой **не** спасается.
   Иначе старая незаполненная история сжигала весь бюджет за один проход.
6. Потраченная заморозка пишется в сам лог: `{ status:'miss', d:<дата>, frozen:true }`.
   **Благодаря этому расчёт детерминирован** и не зависит от порядка вызовов `streakOf`.
7. Бюджет заморозок **помесячный**: 2 заморозки = 2 в сентябре + 2 в октябре.
8. Заморозка за прошлый месяц НЕ списывается из текущего бюджета.
9. `best` (рекорд) считается по тем же правилам, но **сегодняшние дни в него не входят**.

### XP и уровни
`done` 12 · backfill (отметка за прошлую дату) +2 · `skip` 3 · идеальный день 25 ·
новая привычка 20 · заметка 4 · челлендж 40. Уровень: порог ×1.32 (100, 132, 174, 230 …).

### Синхронизация демо ↔ прод
**Пользователь выбрал «обе версии всегда синхронно».** Любая фича добавляется в
`demo/app.js` **и** в `app/src/…`. Логика стрика/расписания должна совпадать посимвольно по смыслу:
`demo/app.js: streakOf()` ↔ `app/src/lib/stats.ts: streakOf()` ↔ SQL `current_streak()`.
Если расходятся — стрик начинает «прыгать» при обновлении страницы.
