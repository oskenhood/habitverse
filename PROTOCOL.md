# 🧠 HabitVerse — протокол работы (читать ПЕРВЫМ)

> **Этот файл — точка входа для любого нового разговора.**
> У ассистента нет памяти между сессиями и нет возможности работать по расписанию.
> Вся преемственность живёт в файлах этой папки.

## 🔴 Правило само-бекапа (обязательно)

В конце **каждой** сессии ассистент обновляет `HANDOFF.md`:
что сделано, что найдено/починено, новые грабли среды, новые предпочтения и формулировки пользователя,
что осталось незакрытым, план на следующую итерацию.
Предыдущая версия копируется в `HANDOFF/archive/YYYY-MM-DD.md`.

Это требование пользователя: он опасается исчерпания лимита чата и хочет,
чтобы новый разговор начинался не с нуля. **HANDOFF.md читается ПЕРВЫМ.**

## Как устроен цикл

```
┌─────────────────────────────────────────────────────────┐
│  В ТЕЧЕНИЕ НЕДЕЛИ                                       │
│  Пользователь накидывает идеи → ассистент дописывает     │
│  их в BACKLOG.md (раздел «📥 Входящие») со статусом      │
│  «💡 идея». Ничего не реализуется сразу, если не сказано │
│  «сделай сейчас».                                        │
├─────────────────────────────────────────────────────────┤
│  РАЗ В НЕДЕЛЮ — «еженедельный заезд»                     │
│  Пользователь пишет условную фразу (см. ниже).           │
│  Ассистент: читает этот файл → BACKLOG.md → CHANGELOG.md │
│  → WEEKLY/*.md → реализует приоритеты → обновляет всё.   │
└─────────────────────────────────────────────────────────┘
```

## Триггерные фразы пользователя

| Фраза | Что делает ассистент |
|---|---|
| **«недельный заезд»** / «weekly update» / «обнови сайт» | Полный цикл: разобрать backlog → реализовать приоритеты P0/P1 → поднять версию → записать в CHANGELOG → создать WEEKLY-заметку → собрать и протестировать |
| **«запиши идею: …»** | Добавить идею в BACKLOG.md → «📥 Входящие», статус 💡, дата. Ничего не кодить |
| **«сделай сейчас: …»** | Реализовать немедленно, обновить CHANGELOG (минорная/патч-версия) |
| **«что у нас по плану?»** | Показать BACKLOG.md по приоритетам + что сделано в последней версии |
| **«сделай бекап себя»** / «обнови handoff» | Обновить `HANDOFF.md` + сложить предыдущую версию в `HANDOFF/archive/` |
| **«собери демо»** | `python3 tools/build-demo.py --src v2` (и `--src demo` для v1.2) + прогнать тесты |

## Правила версионирования

`MAJOR.MINOR.PATCH`

- **PATCH** (1.0.x) — багфиксы, правки текста, мелкие UI-улучшения
- **MINOR** (1.x.0) — новая функция, новый раздел, заметное изменение UX
- **MAJOR** (2.0.0) — переписан стек/архитектура, несовместимые изменения схемы БД

Каждый еженедельный заезд = как минимум MINOR.

## ⚠️ Обязательный регламент после ЛЮБОГО изменения кода

1. **Разработка идёт в `web/`** — это основной проект (продакшен 2.1.0). Папки `demo/`, `v2/` и `app/`
   **заморожены**: `v2/` — визуальный эталон, `app/` — донор Supabase-слоя для фазы 5.4.
   Правило «демо и прод синхронно» отменено релизом 2.0.0: новые фичи делаются только в `web/`.
2. **Перед правкой стилей читать `docs/DESIGN.md`** — там токены и запреты (никакого неона, glow, shimmer).
3. **Проверить основной проект** (после любого изменения `web/`):
   ```bash
   cd habitverse/web && npm install && npm run typecheck && npm run build   # 0 ошибок; build только --webpack
   cd ../tests && npm install && npm run test:web                           # 89 ok / 0 FAIL
   npm run test:web:smoke                                                   # 62 ok (нужен свежий build)
   npm run test:web:static                                                  # 5 ok (нужен свежий npm run export)
   ```
4. **Регрессия архива** (если трогали `v2/`, `demo/` или общие тесты):
   ```bash
   cd habitverse/tests && npm run test:v2 && npm run test:v2:single && npm test && npm run test:single
   ```
   Ожидание: v2 — 84 ok, v1.2 — 121 ok, 0 FAIL. Single-file демо пересобирается
   `python3 tools/build-demo.py --src v2|demo` **только** если меняли сами архивы (обычно — нет).
5. **Продакшен v1.2 (`app/`)** проверять не нужно — он заморожен до фазы 5.4.
6. **Обновить документы:** `VERSION`, `CHANGELOG.md`, `BACKLOG.md` (статусы), `WEEKLY/`-заметку;
   при изменении UX/деплоя/бэкапа — `ИНСТРУКЦИЯ.md` и `web/README.md`.
7. **Обновить `HANDOFF.md`** (и сделать копию в `HANDOFF/archive/`) — обязательно.
8. **Не коммитить** `node_modules`, `.next`, `.env.local`.

## Известные ограничения среды

- `node_modules` и `.next` **не сохраняются** между сессиями → в начале работы всегда `npm install`.
- RAM песочницы ~1 ГБ → сборку Next запускать как `npm run build` (webpack-режим);
  `next build` на Turbopack может быть убит по памяти (exit 137).
- Внутри **файлов** песочница подменяет литерал пути `/home/user` на плейсхолдер —
  в скриптах и конфигах использовать относительные пути или `__dirname`.
- HTML-превью работает в sandbox-iframe **без сети**: внешние CDN-ресурсы не грузятся.
- Фоновые `next start` переживают вызовы bash и держат порты/RAM. `ps`/`pkill` нет, но можно найти
  и убить сирот вручную: `for p in /proc/[0-9]*; do tr '\0' ' ' < $p/cmdline; echo " :: ${p#/proc/}"; done | grep next`,
  затем `kill <PID>` (PID 1 — процесс песочницы, не трогать). Проверено 2026-10-08.
- Push/напоминания в клиентском режиме невозможны (нет сервера) — появятся в фазе 5.4–5.5.

## Контекст продукта

HabitVerse — трекер привычек по мотивам **HabitLink** (App Store, 4.7★), но без его главного
недостатка: в оригинале бесплатно доступна 1 привычка и 1 друг. Здесь ограничений нет.
Второе осознанное отличие — **полное отсутствие геймификации** (XP/уровни/ачивки удалены решением
пользователя в v2.0).

Ключевые механики HabitLink, которые реализованы в основном проекте (`web/`): social tracking
(демо-режим до 5.4), challenges, progress at a glance, customizable schedule, activity feed
с реакциями, customizable UI (8 тем × 2 режима), отметки за прошлые даты, каталог пресетов.
Напоминания и PWA-виджеты — фазы 5.4–5.5.
